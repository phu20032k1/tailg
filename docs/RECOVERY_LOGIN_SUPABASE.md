# TAILG — Recovery checklist for Supabase / login

This checklist is for the current Next.js + Supabase pilot.

## 1. Deployment health

Open `/api/health` on the production deployment.

The endpoint checks:

- Supabase project URL can be parsed.
- Server Secret / Service Role key is available.
- Session signing is ready.
- `app_users` is readable.
- All seven pilot usernames exist.
- `authenticate_user()` exists and can be called.
- Base report table exists.
- V3 labor/equipment/task/weekly tables exist.
- private Storage bucket `site-photos` is available.

A fully prepared database should return `ok: true`, `users: 7`, `missingUsers: []`, `authRpc: "connected"` and `storage: "connected"`.

## 2. Database install order

In Supabase SQL Editor run the repository files in this exact order:

1. `supabase/schema.sql`
2. `supabase/seed.sql`
3. `supabase/functions.sql`
4. `supabase/migrations/20260907_daily_reporting_v3.sql`
5. `supabase/migrations/20260907_weekly_report_assets.sql`
6. Optional real pilot data: `supabase/seed_real_2026_09_07.sql`

All setup files are designed to be rerunnable. `seed.sql` recreates the seven pilot account hashes and the zone assignment data.

## 4. Vercel variables

Preferred variables:

- `SUPABASE_URL`
- `SUPABASE_SECRET_KEY`
- `SUPABASE_STORAGE_BUCKET=site-photos`

Supported integration fallbacks:

- `NEXT_PUBLIC_SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

`SESSION_SECRET` is recommended but is no longer mandatory: the server can derive a session signing key from the Supabase server secret.

Never expose the Supabase Secret / Service Role key through a `NEXT_PUBLIC_*` variable.

## 5. Storage

The application now reconciles `site-photos` at runtime:

- private bucket
- images up to the form limits
- PDF source files for weekly reports
- bucket file ceiling aligned to 30 MB

## 6. If login works but dashboard fails

Older databases may not have `raw_message` and `submitted_at` yet. The data layer now falls back to the V2 report columns so the dashboard stays usable while `/api/health` reports whether the V3 migration is complete.

## 7. Build verification

Every push to `main` runs GitHub Actions:

- `npm install`
- `npm run lint` (`tsc --noEmit`)
- `npm run build`

Do not consider a repair complete until the latest `main` workflow is green and the Vercel status for the same commit is successful.
